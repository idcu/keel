# 0002 入口规格进入机器验：keel-version / project-state 必填，锚点按原文检查

## 背景

v2 把"先点火"列为 P0 却没有任何检查——整套系统的开关交给了自觉；
根 INDEX 缺 keel-version / project-state 也无从判死。同类问题成片：
"写了规则却没写检查"，属于声称强制、实则空转（v3 一次补进 7 项，见 §9.1 注）。
规则只要不能被脚本判死，就等于建议。

## 决定

根 INDEX.md frontmatter 强制 `keel-version` 与 `project-state` 两字段（值域见 §5.2）；
§4.1 点火锚点必须在 CLAUDE.md / AGENTS.md / .cursorrules / .cursor/rules/keel.mdc
中出现原文，改写即 fail。两者均进入 keel-lint 检查范围（§9.1-10）。

## 被否掉的选项

| 选项 | 为什么没选 |
|---|---|
| 保持 v2：规则写在文档里，靠自觉执行 | 实测空转，且文档腐烂无人知，比没文档更危险 |
| project-state 放独立文件 | 破坏"唯一必读入口"，必读文件数与固定成本同时上升 |
| 锚点只写不检查 | 锚点是整套系统的开关，开关不能交给自觉 |

## 后果

- 好处：入口三样（协议 / 路由 / 状态）与点火开关全部可判死。
- 代价：升级方必须补 frontmatter、装锚点；锚点文案自此冻结——
  改文案等于同步改 §4.1 原文、lint 常量与各仓库锚点三处。

## 修订 · v3.13.0：从「入口机器验」扩到「判据机器验」

入口已被判死，但「判据自己有没有被判死」仍靠人记。实测两处账目不一致且都不触发红：
`test-lint` 自报「48 用例 + 2 元检查」，实际另有 `DOC`/`LOCALE`/`PROSE` 未进分母；
DESIGN §9.3 散文写「39 例 fail」，实测 38。

决定：新增 `checks-ledger.py`，§9.1 的 19 项判据单一登记，覆盖状态从 `test-lint.py`
的 `CASES` 自动推导；清单必须含 `checks_ledger`，三档之和等于 19。分母固定 19，
同时单列「已实现 18 项」与 auxiliary/meta，禁止只报百分比。

| 被否掉的选项 | 为什么没选 |
|---|---|
| 手写 `coverage.tsv` | 必然腐烂，且与 test-lint 双源 |
| 把 §9.1-15 补成机器判据 | 项目扩展位；内核补判据会引入第二套真源 |
| 分母混入元检查与动态套件 | 当时判断：混类会让覆盖率失义。**v3.14.0 已修正**：元检查补判死用例后并入并单列；动态套件仍不进 |

后果：账本证明「有用例」，不证明「用例有效」；后者留给变异测试。低覆盖率是结论，不是缺陷。

## 修订 · v3.14.0：分母扩到元检查 + 清单绑定 provenance

- `DOC`/`LOCALE`/`PROSE` 各补一条判死用例（坏脚本副本 / `LC_ALL` 泄漏赋值 / 旧版本
  README），进入「含元检查」分母；`§9.3-BUDGET` 已有用例 20，给正式编号。
  分母 19 → 22 → 23，三个口径同屏打印。`§9.1-15` 仍不给编号：**给不了判死用例就不登记**。
- 清单增 `provenance`：`commit`、`dirty`/`dirty_files`、四个判据文件 sha256、平台、
  locale、`generated_at`。`check-verify-report.py --repo <发布仓>` 在 commit ≠ HEAD、
  自称干净却有未提交文件、sha256 已变时 FAIL；`release.sh` 推送前跑同一条。
  自检 11 → 17；v3.14.1 再加 3 条 CLI 级用例（17 → 20）——「只给 `--repo` 不给
  `--claims`」那条路径曾静默绿。
- 诚实边界：只证明「清单与代码自洽」，**刻意不写「防篡改」**。

## 修订 · v3.15.0：入口接线审计 + 变异试点

账本证明「判据有负例」、provenance 证明「清单与代码自洽」；两者都不回答
「某个 CLI 入口是否真的被跑过」。v3.14.1 三个缺陷全同型：判据在，调用路径没接上。

- `checks/wiring/test-wiring.py`：26 个入口 × 24 条判死用例（退出码 + 输出片段 +
  磁盘副作用），矩阵进清单 `wiring`；缺用例显式 `wiring=0`，本仓无该脚本标 `n/a`。
- `checks/mutation/`：9 条 §9.1 × 16 变异体，3 类算子；得分进清单但**不进发布门禁**——
  低分是结论，把存活变异体判 FAIL 等于逼下一轮删难杀的变异体抬分。
- 两者都不替代人工评审：接线审计测不到语义错，变异测试测不到接线错与跨文件/跨版本行为。
