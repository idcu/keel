# 0018 门面散文数字机器校验：test-lint 增 PROSE 元检查

## 背景

§9.1-17（v3.4.5）把「徽章 / CHANGELOG / keel-version」三副本交给机器守之后，
2026-11-02 全维度评估实测发现**下一层照样漂**：README 与 DESIGN.md **散文**里的
`--ref v3.4.6`、`keel-version 3.4.6`、「自测必须 39/39」「41 例」「42/42」共 14 处，
全部滞后于真值（3.4.11 / 43/43）。lint 的 17 项与 DOC 逐字检查都管不到散文——
这是 §9.1-17 修复过的 Lint Leakage 在自家文档上的同型复现：
**判据存在但覆盖有洞，等于那一层没有判据。**

## 决定

在 test-lint.py 增 **PROSE 元检查**（与 DOC 检查同族，不进用例分母）：

- **真源**：用例数 = `len(CASES)`（总分母 +1 元检查，不受 `--only` 影响）；
  版本 = `keel/INDEX.md` frontmatter 的 `keel-version`。
- **目标**：仓根 `README.md` + `DESIGN.md`（存在才查）。只守门面——
  `docs/`、`pitfalls/`、`decisions/` 历史叙述密集，不在覆盖内。
- **规则**：
  ① `--ref vX.Y.Z`（非围栏区，无豁免）必须 == 当前版本；
  ② `keel-version` 散文形态（冒号形态是 frontmatter 示例，不算）必须 == 当前版本；
  ③ 含「自测/用例/test-lint」行内的 `N/N` 比分（全区域含代码块注释）必须 == 总分母；
  ④ 同行条件的 `N 用例` / `N 例` 必须 == 用例数。
- **豁免**：行内带任一 `vX.Y.Z`（≠当前版本）视为历史叙述（规则②③④）——
  由此成立一条写作约定：**讲历史必须带当时版本号**；
  历史叙述里举例 `--ref` 用 `<旧版本>` 占位（规则①不豁免，否则真漂移同形态漏判）。

## 被否掉的选项

| 选项 | 为什么没选 |
|---|---|
| 扩展 lint 第 18 项进 keel-lint.sh | 内核只依赖 bash/awk/sed，多目标门面扫描会拖慢内核（当前亚秒级）；且这属「门面一致性」，与 DOC 检查同族，归自测而非内核 |
| 从真源**生成** README/DESIGN（模板化） | 违背零构建、纯文本约束；门面文档的修辞自由不该被模板杀死——数字在语境里有承诺语气（「必须 43/43」），生成会把它磨平 |
| 只手改数字不加判据 | §9.1-17 的教训原文：「价值不在补上这一版，在拦住下一次」——10-04 手改徽章、11-02 散文又漂，已演过两轮 |
| 代码块整体跳过 | README「# 5. 自测：必须 42/42」、DESIGN「# 41 例 + 元检查」都漂在代码块注释里——块内承诺也是承诺，规则③④必须全区域扫 |

## 失效场景（诚实边界）

1. 只守两个门面文件；其他文档里的比分/版本叙述不查（历史区故意不查）。
2. 「N 例」只认「数字+空白+例」形态；「四十二例」等写法抓不住（门面文件无此写法）。
3. 历史叙述若忘了带 `v` 前缀版本号会被误判为现在时——这是故意选择的严格：
   误报迫使作者补上版本号，叙述反而更诚实。
4. `--ref` 规则无豁免：事故回顾里写具体旧版本号会被判（DESIGN §12.3 已改占位写法）。

## 影响

- `test-lint.py`：新增 `check_prose_numbers()`，main() 尾部报告（两仓同步）。
- README（两仓）/ DESIGN.md：14 处漂移修正；README「状态」节的守护说明改写实。
- 写作约定：门面文档讲历史比分必须带 `vX.Y.Z`；举例 `--ref` 历史事故用占位。
