## 本轮完成

- [x] **遵守率补回滚维度**（P0）：初版只记 lint 命中，漏了「放行后被回滚」——
      那恰恰是 lint 自己看不见的一类不遵守。
      实测同一假仓：**66.7% → 33.3%，虚高一倍**
- [x] **回滚匹配用精确格式** `git log --grep='^Revert "'`——实测 `-i --grep=revert`
      会把"实现 revert 按钮的功能"误计
- [x] **预算超限率聚合**（P1）：`load-estimate.sh` 每轮写 `load.jsonl`（含 `over=`），
      报告一并给出超限率
- [x] **install.sh 进 CI**（P1）：空项目 → 装 → 钩子 100755 → 锚点判死 → 补上转绿，
      四步全在本地实测过才写进 workflow
- [x] **修一个 P0 假成功**：`install.sh` 用相对路径 `keel` 调 lint，
      而该入参是**相对 cwd** 解析的 → cwd 在发布仓时，校验的是发布仓自己（绿），
      新装项目根本没被检查。**比不验证更坏**
- [x] **修 install.sh 吞原因**：原来把 lint 输出丢 `/dev/null` 只说"未通过"，
      现打印判死原因 + 锚点缺失的具体指引
- [x] **修自己引入的回归**：上轮把项目仓索引覆盖到发布仓，挤掉模板的连接池坑登记
      → 发布仓 lint 报 2 条 fail
- [x] **修 awk 字符串比较 bug**：`v > max` 走字典序，**峰值永远偏小**（18999 < 6000）
- [x] 新坑 2 条：`awk-string-vs-number-compare`（P2）、`install-verifies-wrong-dir`（**P0**）
- [x] ADR 0009 补 v3.3.1 修正段；设计稿 §11.2 口径同步
