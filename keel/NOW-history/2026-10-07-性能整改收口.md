## 第十九轮：段 2 流式结算（v3.4.8 → v3.4.9）

- v3.4.8 先发"流式扫描"；随后两次尝试（#2 合成字段、#4 叠在流式之上）**均实测回退**
  （2× / 2.8× 慢）——热点确认为 **O(查表调用次数 × 表行数)**，只改外层遍历无效
- v3.4.9 按校准方向落地「段 2 流式结算」：单趟扫 FMQ、文件边界用累积变量结算，
  全程不调 `fmq_set`（存在性＝表中出现该键的行，值可空）
- 实测：macOS 28/29/30s → 9/10/6s（**3.3×**）· Windows 652 → 182s（**3.4×**）·
  套件 ~12min → **11.7s** · 43/43
- 累计 vs v3.4.7：64-75s → 6-10s（**7-10×**）

## 第二十轮：段 12 流式结算（v3.4.10）

- 逐段画像定位 8.03s 集中在段 12（decisions 两循环合计 ~35 次 `fmq_set`）
- 改流式：单趟扫 FMQ 过滤 `decisions/*.md`、边界结算 type/created/superseded-by；
  顺带删掉只为两循环服务的 `find` + DECL 中间文件
- 实测：macOS 9s → **0.67s（亚秒）** · Windows 110 → 63s（**1.75×**）· 43/43
- 累计：64-75s → 0.67s（**约 100×**）

## 第二十一轮：链接提取并入构建趟（v3.4.11）

- 构建阶段三趟 → **两趟**：同一 awk 读文件时同时写 FMQ 与 LINKS，收尾 `sort -u` 一次；
  兜底：合并趟整体失败时单独重跑链接提取（防段 9 孤儿全量误报的历史坑）
- 实测：macOS **~3-5%** · Windows **~5%**（双平台一致）· 43/43 · DOC 逐字一致
- 坑（记）：同一脚本跨轮绝对值可比性差（宿主负载 / 磁盘缓存 / Defender），
  可信口径 = **同会话交替 A/B 的配对差**，不是跨轮绝对值
